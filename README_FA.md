# راهنمای فارسی راه‌اندازی پرسشنامهٔ XM

## ۱. محتویات بسته

```text
index.html                 صفحهٔ اصلی
styles.css                 ظاهر، رنگ‌ها و تعریف فونت Dana
config.js                  نشانی اتصال به گوگل
app.js                     منطق فرم، پیش‌نویس، بازبینی و رسید
data.js                    متن سؤال‌ها، گزینه‌ها و راهنمای مقیاس
assets/                    دو لوگوی ارائه‌شده
assets/fonts/              محل افزودن فایل‌های دارای مجوز Dana
google-apps-script/Code.gs  منطق دریافت و ذخیرهٔ پاسخ‌ها
google-apps-script/Schema.gs تعریف سؤال‌ها برای اعتبارسنجی سرور
tools/build-schema.mjs     ساخت Schema.gs از data.js
tests/                     آزمون‌های بک‌اند و مرورگر
.nojekyll                  انتشار مستقیم فایل‌های ایستا در GitHub Pages
```

نیازی به PHP، پایگاه دادهٔ جداگانه، npm install یا مرحلهٔ build برای اجرای سایت نیست. Node.js فقط برای ابزار تولید طرح سؤال‌ها و آزمون‌ها استفاده می‌شود.

**وضعیت اولیه:** `config.js` عمداً نشانی خالی دارد. در این حالت همهٔ مراحل فرم قابل مشاهده است، اما ثبت نهایی غیرفعال است و هشدار پیش‌نمایش نشان داده می‌شود. اطلاعات حساب، کلید خصوصی یا رمز عبور در بسته وجود ندارد.

## ۲. ساخت مخزن و تعیین نشانی سایت

۱. در GitHub یک مخزن برای سایت بسازید؛ برای نمونه `xm-survey`.
۲. ZIP را روی رایانه باز کنید. **محتویات پوشهٔ `xm-survey`** را در ریشهٔ مخزن بارگذاری کنید؛ نه ZIP را و نه یک پوشهٔ اضافی پیرامون فایل‌ها. `index.html` باید مستقیماً در ریشهٔ مخزن باشد.
۳. در تنظیمات مخزن به **Settings → Pages** بروید. در بخش انتشار، **Deploy from a branch** و سپس شاخهٔ `main` و مسیر `/(root)` را انتخاب کنید و ذخیره کنید.
۴. پس از اتمام انتشار، نشانی نمایش‌داده‌شدهٔ GitHub Pages را باز کنید. نشانی نمونه:

```text
https://YOUR_USERNAME.github.io/xm-survey/
```

۵. از HTTPS استفاده کنید. نشانی دقیق سایت را نگه دارید. اگر دامنهٔ اختصاصی به کار می‌برید، تنظیم `SITE_ORIGIN` در مرحلهٔ بعد باید مربوط به همان دامنهٔ نهایی باشد.

> فرم در ابتدا پیش‌نمایش است. بعد از تنظیم گوگل، فقط `config.js` را به‌روزرسانی می‌کنید و انتشار GitHub مجدداً انجام می‌شود.

## ۳. ساخت Google Sheet خصوصی

۱. با حساب مسئول پژوهش یک Google Sheet خالی بسازید.
۲. شناسهٔ فایل را از نشانی آن بردارید؛ فقط بخش بین `/d/` و `/edit`:

```text
https://docs.google.com/spreadsheets/d/SPREADSHEET_ID/edit
```

۳. فایل را عمومی نکنید و از **Publish to web** برای آن استفاده نکنید. دسترسی را تنها به اعضای مجاز تیم پژوهش بدهید.
۴. از **Extensions → Apps Script** پروژهٔ اسکریپت را باز کنید. می‌توانید پروژهٔ مستقل Apps Script نیز بسازید، به شرط آنکه حساب اجراکننده به Sheet دسترسی ویرایش داشته باشد.
۵. کد پیش‌فرض `Code.gs` را با محتوای `google-apps-script/Code.gs` جایگزین کنید.
۶. یک فایل Script دیگر به نام `Schema` بسازید؛ ویرایشگر پسوند `.gs` را اضافه می‌کند. محتوای `google-apps-script/Schema.gs` را در آن کپی کنید.
۷. هر دو فایل باید در **همان پروژهٔ Apps Script** باشند. ذخیره کنید. محیط اجرا باید V8 باشد.

## ۴. تنظیم Script properties

در **Project Settings → Script properties** دو ویژگی زیر را اضافه و ذخیره کنید:

| نام | مقدار |
| --- | --- |
| `SPREADSHEET_ID` | شناسهٔ فایل Sheet، نه نشانی کامل و نه شناسهٔ تب |
| `SITE_ORIGIN` | فقط پروتکل و دامنهٔ سایت، بدون مسیر و بدون اسلش انتهایی |

برای سایت نمونهٔ بالا:

```text
SITE_ORIGIN = https://YOUR_USERNAME.github.io
```

این مقادیر اشتباه‌اند:

```text
https://YOUR_USERNAME.github.io/xm-survey/
https://YOUR_USERNAME.github.io/
http://YOUR_USERNAME.github.io
```

برای دامنهٔ اختصاصی نمونه:

```text
SITE_ORIGIN = https://survey.example.org
```

از فهرست توابع بالای ویرایشگر، **checkSetup** را انتخاب و **Run** را بزنید. مجوزهای لازم را فقط پس از بررسی کدی که در پروژهٔ خود کپی کرده‌اید تأیید کنید. خروجی باید شامل `Setup OK` باشد. این تابع دسترسی به فایل و قالب تنظیمات را بررسی می‌کند؛ پاسخ آزمایشی نمی‌سازد و موفقیت آن جایگزین آزمون انتهابه‌انتها نیست.

در صورت خطای دسترسی، حساب اجراکننده باید مالک یا ویرایشگر همان Sheet باشد. `doPost` را با دکمهٔ Run آزمایش نکنید؛ این تابع به درخواست واقعی فرم نیاز دارد.

## ۵. انتشار Web app گوگل

۱. در Apps Script گزینهٔ **Deploy → New deployment** را انتخاب کنید.
۲. نوع انتشار را **Web app** قرار دهید.
۳. **Execute as** را روی **Me** قرار دهید؛ یعنی اجرا با حساب مالک انتشار.
۴. **Who has access** را روی **Anyone** قرار دهید تا پاسخ‌دهنده نیاز به ورود به حساب گوگل نداشته باشد. «Anyone with Google account» جایگزین این حالت نیست.
۵. انتشار را انجام دهید و نشانی Web app را کپی کنید. نشانی باید با `/exec` پایان یابد:

```text
https://script.google.com/macros/s/DEPLOYMENT_ID/exec
```

۶. در `config.js` فقط مقدار `endpoint` را تغییر دهید:

```javascript
window.XM_CONFIG = {
  endpoint: 'https://script.google.com/macros/s/DEPLOYMENT_ID/exec',
  timeoutMs: 60000
};
```

۷. تغییر را در GitHub ذخیره/Commit کنید و منتظر پایان انتشار Pages بمانید. صفحهٔ سایت را دوباره بارگیری کنید. هشدار پیش‌نمایش باید حذف شده باشد.

نکات:

- از نشانی آزمایشی `/dev` یا نشانی ویرایشگر Apps Script استفاده نکنید.
- اگر حساب سازمانی گزینهٔ دسترسی **Anyone** را نمی‌دهد، مدیر Workspace باید محدودیت را بررسی کند؛ این بسته آن محدودیت را دور نمی‌زند.
- بازکردن مستقیم `/exec` فقط پیام فعال‌بودن سرویس را نشان می‌دهد؛ اثبات ذخیره‌شدن پاسخ نیست.
- پس از تغییر کد Apps Script، از **Deploy → Manage deployments → Edit → New version → Deploy** نسخهٔ تازه را منتشر کنید. ذخیرهٔ کد به‌تنهایی نسخهٔ منتشرشده را عوض نمی‌کند. اگر انتشار جدیدی با نشانی متفاوت ساختید، `config.js` را نیز تغییر دهید.
- انتقال فرم با POST به iframe و بازگشت رسید با `postMessage` انجام می‌شود؛ برای این پیاده‌سازی از راهکار `fetch` با `no-cors` استفاده نکنید. فرم تنها پس از رسید موفق سرور، موفقیت نشان می‌دهد.

## ۶. افزودن فونت Dana

فایل‌های فونت Dana در ورودی ارائه نشده‌اند؛ بنابراین در این بسته وجود ندارند. دو فایل وب‌فونت دارای مجوز مناسب خود را با نام دقیق زیر اضافه کنید:

```text
assets/fonts/Dana-Regular.woff2
assets/fonts/Dana-Bold.woff2
```

بزرگی و کوچکی حروف نام فایل‌ها مهم است. تا پیش از افزودن فونت، مرورگر از Tahoma/Arial یا فونت sans-serif سیستم استفاده می‌کند. تعریف `@font-face` و وزن‌های ۴۰۰ و ۷۰۰ در `styles.css` آماده است. فایل فونت تصادفی را صرفاً تغییرنام ندهید؛ نوع و وزن واقعی فایل باید درست باشد. انتشار فایل در مخزن و روی وب باید مطابق مجوز فونت باشد.

## ۷. آزمون نهایی پیش از دعوت مشارکت‌کنندگان

این آزمون را روی **نشانی منتشرشدهٔ HTTPS** و ترجیحاً در پنجرهٔ خصوصی انجام دهید:

- [ ] هر دو لوگو، نوشته‌های فارسی و نمایش موبایل را بررسی کنید.
- [ ] خالی‌گذاشتن هر سؤال باید مانع ادامه شود.
- [ ] با انتخاب وجود متولی، سؤال عنوان متولی نمایش داده شود و اجباری باشد؛ با انتخاب نبود متولی مخفی شود.
- [ ] انتخاب «سایر صنایع» باید نام صنعت را اجباری کند.
- [ ] ذخیرهٔ پیش‌نویس و بارگیری مجدد صفحه را آزمایش کنید.
- [ ] رتبه‌های هر سؤال اهمیت باید سه انتخاب متفاوت باشند؛ چالش‌ها باید دقیقاً سه مورد باشند.
- [ ] راهنمای مقیاس، صفحهٔ بازبینی همهٔ پاسخ‌ها و بازگشت از ویرایش را بررسی کنید.
- [ ] قبل از تأیید نهایی نباید پاسخ در Sheet ثبت شود.
- [ ] یک پاسخ با نام مشخص «آزمون انتشار» ثبت کنید و کد پیگیری را نگه دارید.
- [ ] تب `XM_Responses` باید ساخته شده و دقیقاً یک ردیف برای آن پاسخ داشته باشد.
- [ ] کد پیگیری، تاریخ شمسی و ساعت تهران روی رسید باید با ستون‌های Sheet یکسان باشند.
- [ ] بارگیری دوبارهٔ صفحهٔ رسید نباید ردیف جدید بسازد.
- [ ] اگر رسید دریافت نشد، فقط دکمهٔ تلاش مجدد همان فرم را بزنید؛ شناسهٔ ثابت باید مانع ثبت تکراری همان پاسخ شود.
- [ ] فرم را در مرورگر موبایل مورد استفادهٔ مخاطبان و بدون ورود به گوگل نیز بررسی کنید.

پس از آزمون، ردیف‌های آزمایشی را در صورت نیاز حذف کنید؛ **ردیف اول، ترتیب ستون‌ها و نام تب را تغییر ندهید.** پیش از حذف، رسید آزمایشی را نگه دارید. حذف یک ردیف، سابقهٔ جلوگیری از ثبت مجدد همان شناسه را هم حذف می‌کند؛ بنابراین آزمون تلاش مجدد را قبل از پاک‌سازی انجام دهید.

## ۸. داده‌های ذخیره‌شده

تب `XM_Responses` با اولین پاسخ معتبر به‌صورت خودکار ساخته می‌شود. هر پاسخ یک ردیف دارد. ابتدای ردیف:

| ستون | کاربرد |
| --- | --- |
| `submission_id` | شناسهٔ ثابت یک مجموعه پاسخ، برای جلوگیری از ثبت تکراری |
| `payload_sha256` | هش پاسخ نرمال‌شده برای کنترل ناسازگاری در ارسال دوباره |
| `کد پیگیری` | کد رسید؛ این کد رمز دسترسی یا لینک بازیابی عمومی نیست |
| `تاریخ ثبت شمسی` | تاریخ تقویم هجری شمسی، مانند `1405/01/01` |
| `ساعت ثبت تهران` | ساعت ۲۴ساعته، مانند `14:35:09` |
| `submitted_at_utc` | زمان UTC در قالب ISO برای تحلیل و تطبیق |
| `survey_version` | نسخهٔ ساختار پرسشنامه |

سپس ستون‌های سؤال‌ها قرار می‌گیرند. پاسخ‌های گزینه‌ای هم متن گزینه و هم کد یک‌مبنایی گزینه را دارند. رتبه‌ها در ستون‌های `rank_1` تا `rank_3` همراه شناسهٔ شایستگی ذخیره می‌شوند. سه انتخاب چالش با `choice_1` تا `choice_3` ذخیره می‌شوند؛ ترتیب این سه ستون رتبهٔ اهمیت نیست. در سؤال متولیِ نامشمول، مقدار خالی ذخیره می‌شود.

تاریخ و ساعت از **زمان سرور با منطقهٔ `Asia/Tehran`** به دست می‌آیند، نه ساعت دستگاه پاسخ‌دهنده؛ دو ستون مستقل و متنی هستند تا تنظیمات محلی Sheet آن‌ها را به تاریخ میلادی تبدیل نکند. ارقام برای تحلیل‌پذیری لاتین‌اند. در تلاش مجدد، رسید با تاریخ و ساعت ثبت اولیه بازگردانده می‌شود.

متن‌های شروع‌شونده با نشانهٔ فرمول به‌صورت متن امن ذخیره می‌شوند تا ورودی پاسخ‌دهنده به فرمول Sheet تبدیل نشود.

## ۹. محرمانگی و محدودیت‌های عملیاتی

- نام فرد و سازمان جمع‌آوری می‌شود؛ بنابراین این پرسشنامه «ناشناس» نیست. مسئول پژوهش باید مجوز جمع‌آوری، سیاست نگهداری و دسترسی به داده‌ها را تعیین کند.
- Sheet و پاسخ‌های واقعی را در GitHub، نسخهٔ عمومی سایت یا فایل نمونه قرار ندهید. عمومی‌بودن کد سایت به معنی عمومی‌کردن پاسخ‌ها نیست.
- `SITE_ORIGIN` مقصد امن ارسال رسید است؛ **احراز هویت فرستنده یا مانع ارسال مستقیم درخواست به سرویس نیست**. سرویس عمومی است. فیلد تله و اعتبارسنجی، جایگزین CAPTCHA، محدودسازی نرخ یا کنترل پیشرفتهٔ سوءاستفاده نیستند.
- جلوگیری از تکرار برای **همان شناسهٔ ارسال** است، نه شناسایی یک شخص در چند مرورگر یا دستگاه. یک نفر می‌تواند پرسشنامهٔ جدیدی با شناسهٔ تازه بسازد.
- پیش‌نویس در localStorage همان مرورگر و همان دامنه ذخیره می‌شود، نه در گوگل و نه در دستگاه دیگر. پاک‌کردن داده‌های مرورگر، حالت خصوصی یا تغییر دامنه می‌تواند آن را از دسترس خارج کند. روی دستگاه مشترک، پیش‌نویس را پاک کنید.
- پس از تأیید و آغاز ارسال، پاسخ‌ها برای تلاش مجدد قفل می‌شوند. در خطای قطعی اعتبارسنجی، امکان اصلاح برمی‌گردد. در تأخیر یا خطای ذخیره، برای جلوگیری از تناقض، همان پاسخ دوباره ارسال می‌شود.
- پس از دریافت رسید موفق، پیش‌نویس محلی پاک می‌شود و فقط رسید باقی می‌ماند. کد پیگیری را نگه دارید؛ این بسته صفحهٔ عمومی جست‌وجو یا بازیابی پاسخ با کد ندارد.
- Apps Script و Sheets محدودیت سهمیه و هم‌زمانی دارند. برای مطالعهٔ پرترافیک، قبل از انتشار گسترده بار مورد انتظار را ارزیابی کنید؛ این بسته تضمین ظرفیت نامحدود ندارد.
- دسترسی مخاطبان به سرویس گوگل را روی شبکه‌های هدف آزمایش کنید. اختلال شبکه یا محدودیت دسترسی ممکن است مانع ثبت یا دریافت رسید شود.
- برای ویرایش/حذف پاسخ نهایی، فرآیند تیم پژوهش لازم است؛ فرم فقط قبل از ارسال امکان ویرایش می‌دهد.

## ۱۰. متن و ساختار پژوهش

- متن سؤال‌های اصلی و راهنمای مقیاس در `data.js` نگهداری می‌شود. سؤال‌های مشخصات پاسخ‌دهنده و سازمان بهبود یافته‌اند.
- متن معرفیِ ارائه‌شده از سؤال باز «اختیاری» یاد می‌کند؛ برای حفظ متن اصلی دستکاری نشده است. اطلاعیهٔ آشکار ابتدای فرم تصریح می‌کند که طبق نیاز این نسخه، **همهٔ پاسخ‌ها از جمله تشریحی الزامی‌اند**.
- متن ورودی برای ۱۴ شایستگی سؤال ارزیابی مستقل دارد، ولی فهرست رتبه‌بندی و چالش‌ها ۱۵ شایستگی دارد. سؤال پانزدهم از روی حدس ساخته نشده است. پیش از تغییر این ساختار، متن مصوب پژوهش لازم است.
- بخش مشخصات شماره‌گذاری جدا دارد؛ شمارهٔ سؤال‌های اصلی از ۱ شروع می‌شود. شناسه‌های پایدار سؤال‌ها مستقل از این شماره‌ها هستند.
- راهنمای وضعیت کلی پنج سطح دارد و گزینه‌های ارزیابی شایستگی شش سطح؛ راهنمای فرم این تفاوت را توضیح می‌دهد و تبدیل عددی بین آن‌ها انجام نمی‌دهد.
- ظاهر این نسخه مستقلاً پیاده‌سازی شده است؛ تطبیق بصری با صفحهٔ مرجع SurveyMonkey تأیید نشده است.

اگر `data.js` را تغییر می‌دهید، با Node.js اجرا کنید:

```bash
node tools/build-schema.mjs
node tools/build-schema.mjs --check
node --test tests/backend.test.mjs
```

سپس `Schema.gs` تازه را همراه کد لازم در Apps Script جایگزین و نسخهٔ تازه منتشر کنید. تغییر ساختار سؤال‌ها/گزینه‌ها در میانهٔ جمع‌آوری می‌تواند معنای داده‌ها و پیش‌نویس‌ها را تغییر دهد. برای تغییر اساسی، `version` و کلیدهای ذخیرهٔ محلی را بازنگری کنید و از Sheet/انتشار جدا استفاده کنید. ناسازگاری سرستون‌ها عمداً جلوی ثبت را می‌گیرد تا ستون‌های اشتباه با پاسخ پر نشوند.

## ۱۱. آزمون‌های تحویل و اجرای محلی

آزمون‌های انجام‌شده در این بسته:

- **۹ آزمون بک‌اند موفق:** تطبیق ساختار کلاینت و سرور، الزام پاسخ‌ها، شرایط متولی/صنعت، سه انتخاب متمایز، نوع داده و طول مجاز، ذخیرهٔ امن و بدون تکرار، رسید، تنظیم origin و تبدیل شمسی در بازهٔ ۲۰۰۰ تا ۲۰۵۰.
- **آزمون مرورگر Chromium در عرض‌های ۱۲۸۰، ۳۹۰ و ۳۲۰ پیکسل موفق:** مسیر کامل فرم، پیش‌نویس و بازیابی، اعتبارسنجی، راهنما، رتبه‌بندی، چالش، بازبینی/ویرایش، تأیید، نرسیدن رسید و تلاش مجدد، رسید پس از بارگیری مجدد و شروع مجدد؛ بدون خطای JavaScript یا اسکرول افقی در مراحل بررسی‌شده.
- پاسخ سرویس گوگل در آزمون مرورگر **شبیه‌سازی شده** است. انتشار واقعی در حساب GitHub/Google شما و مجوزها، iframe واقعی گوگل و سهمیه‌های حساب هنوز نیازمند آزمون مرحلهٔ ۷ هستند. آزمون خودکار معادل تأیید همهٔ مرورگرها یا ممیزی جامع امنیت/دسترس‌پذیری نیست.

برای مشاهدهٔ محلی از داخل پوشهٔ پروژه، مثلاً:

```bash
python3 -m http.server 8000
```

سپس `http://localhost:8000` را باز کنید. فایل را صرفاً با دوبارکلیک و `file://` باز نکنید. اجرای محلی برای رابط کاربری است؛ اتصال واقعی این بسته برای دامنهٔ HTTPS تنظیم می‌شود. برای اجرای آزمون بک‌اند از Node.js نسخهٔ جدید (پیشنهاد: ۲۰ یا بالاتر) استفاده کنید.

آزمون مرورگر اختیاری است و برای اجرای سایت نیازی به نصب آن نیست:

```bash
npm install --no-save --package-lock=false playwright-core
npx playwright-core install chromium
node tests/browser.mjs
```

می‌توان مسیر مرورگر نصب‌شده را با `CHROMIUM_PATH` و مسیر ماژول Playwright را با `PLAYWRIGHT_MODULE` تعیین کرد. آزمون مرورگر پاسخ واقعی به Google Sheets نمی‌فرستد. پوشهٔ `node_modules` را در GitHub بارگذاری نکنید.

## ۱۲. عیب‌یابی سریع

| نشانه | بررسی |
| --- | --- |
| سایت 404 می‌دهد | `index.html` در ریشهٔ مسیر انتخاب‌شده، شاخه و مسیر Pages، و پایان انتشار را بررسی کنید. |
| هشدار پیش‌نمایش حذف نمی‌شود | `endpoint` خالی یا نامعتبر است؛ نشانی دقیق `/exec` و انتشار مجدد `config.js` را بررسی کنید. |
| تصویر یا فونت نمایش داده نمی‌شود | مسیر نسبی، نام و بزرگی/کوچکی حروف فایل‌ها را بررسی کنید؛ Dana تا افزودن فایل‌ها موجود نیست. |
| ورود به گوگل از پاسخ‌دهنده خواسته می‌شود | انتشار باید Execute as Me و دسترسی Anyone باشد؛ محدودیت Workspace را بررسی کنید. |
| رسید نمی‌رسد | `SITE_ORIGIN` بدون مسیر/اسلش، دامنهٔ واقعی، مجوزهای انتشار، شبکه و تنظیمات iframe/حریم خصوصی مرورگر را بررسی کنید. پاک‌کردن پیش‌نویس راه‌حل نیست؛ تلاش مجدد همان شناسه را استفاده کنید. |
| ردیف ذخیره شده ولی رسید نیامده | معمولاً مسیر بازگشت رسید یا شبکه نیاز به بررسی دارد؛ تنظیم origin را اصلاح و همان فرم را دوباره ارسال کنید تا رسید قبلی بازگردد. |
| پیام خطای ذخیره‌سازی تکرار می‌شود | `checkSetup`، دسترسی Sheet، سهمیه‌ها، بخش Executions در Apps Script و تغییرنکردن سرستون‌ها را بررسی کنید. |
| بعد از تغییر کد، رفتار قدیمی باقی است | نسخهٔ تازهٔ Web app را Deploy و کش صفحه را تازه کنید؛ در صورت تغییر نشانی، config را اصلاح کنید. |
| پاسخ‌های قبلی دیده نمی‌شوند | پیش‌نویس فقط به همان مرورگر، دستگاه و دامنه تعلق دارد؛ اطلاعات از دستگاه دیگر همگام نمی‌شوند. |

**پایان راه‌اندازی:** تنها پس از ثبت آزمایشی موفق روی سایت واقعی و تطبیق رسید با Sheet، لینک عمومی پرسشنامه را توزیع کنید.
